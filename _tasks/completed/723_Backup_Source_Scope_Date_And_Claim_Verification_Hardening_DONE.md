# Task 723: Backup Source Scope Date And Claim Verification Hardening

## Type

Backup Tool / Final Answer Verification

## Severity

Medium

## Evidence

Round 7 full prompt 08 initially backed up the repo root:

```text
[BACKUP] source=. dest=project_tmp/backup_20260513_143000 matched=28746 copied=28746 manifest_files=1 errors=0 verification_ok=true
```

The system date is `2026-05-07`, but that generated backup path used `20260513`. The bad generated 1.5GB backup was removed during validation.

A narrow safety patch was applied after the full round:

- root backup source is remapped to `src` when `src/` exists
- default include pattern changed from `**/*` to `**/*.rs`

Focused rerun:

- `project_tmp/round7_sessions/prompt_08_rerun_after_backup_patch_s_1778143514_95946000`
- trace: `[BACKUP] root source remapped to src for source-file backup contract`
- trace: `source=src ... matched=322 copied=322 ... verification_ok=true`

Remaining issue in final answer:

```text
File 'backup_manifest.txt' was claimed but could not be verified on disk
```

The manifest exists, but the claim verifier treated the basename as an unverified relative path.

## Problem

The backup tool is now safer, but the runtime still needs formal hardening for scope, generated timestamp sanity, and final-claim verification against tool evidence.

## Requirements

- Add tests for root-source remapping and default include pattern safety.
- Ensure backup destination timestamps are generated by Elma or checked against current local time when the model supplies a timestamped path.
- Prevent backup into future-dated directories unless explicitly requested by the user.
- Expand default excludes for root-level backup attempts to avoid generated/vendor/archive directories.
- Teach finalization verifier that a basename claim such as `backup_manifest.txt` is supported when backup tool evidence provides a full manifest path ending in that basename.
- Record backup scope decisions in transcript-native rows.

## Acceptance Criteria

- [ ] Prompt 08 never backs up repo root/generated/vendor folders by default.
- [ ] Backup path dates match current local date unless user explicitly requests otherwise.
- [ ] Final answer does not append a false unsupported-claim warning for `backup_manifest.txt`.
- [ ] `cargo test -q backup` covers source remapping and manifest claim support.
